# 図面差分抽出ツール

2枚のPDF図面を比較して、変更された箇所を自動で抽出します。

配布物は **`図面差分抽出ツール.html` の1ファイルだけ**です。
このファイルをブラウザ（Chrome / Edge）で開けば動きます。
インストールも、インターネット接続も、Pythonなどの実行環境も要りません。

図面はブラウザの中だけで処理され、外部のサーバーには一切送信されません。

## 使い方

1. `図面差分抽出ツール.html` をダブルクリックして開く
2. 左に**改訂前**、右に**改訂後**のPDFを入れる（ドラッグ＆ドロップ可）
3. 「差分を抽出する」を押す
4. 変更箇所の一覧が出るので、クリックすると新旧の比較が表示される
5. 必要に応じて保存する
   - **変更箇所マーキングPDF** … 改訂後の図面に、変更箇所を赤枠と通し番号で囲んだPDF
   - **新旧比較画像（ZIP）** … 変更箇所ごとの新旧並べ画像と `変更箇所一覧.csv`

A1サイズの図面で1ページあたり数秒かかります。

## 何を「変更」として拾うか

| 表示 | 意味 |
|---|---|
| 旧 / 新 | 文字・寸法値が書き換わった箇所 |
| 位置移動 | 文字は同じで、位置だけが動いた箇所 |
| 図形のみの変更 | 文字を伴わない、線や記号だけの変更 |

「軽微な差も表示する」にチェックを入れると、作図しなおしによる寸法補助線の
引き直しなど、意味を持たない細かい差も表示します。

## 仕組み

PDF内のベクター図形（線・曲線・矩形）を1本ずつ座標で突き合わせています。

画像に変換してから比較する方式は採っていません。CAD図面のハッチングは
0.1pt程度の細い斜線の集まりで、再プロット時のごく僅かな位置差でも
画素上では「別の線」になってしまい、図面全体がノイズだらけになって
実際の変更が埋もれるためです。

主な処理は次の通りです。

1. **向きの正規化**
   同じ図面でも、回転して保存されたPDFとそうでないPDFがあります
   （A3横で保存したものと、A3縦を90°回転して横に見せているもの）。
   そのまま座標を比べると全要素が別物になるため、
   まず「画面に表示されるときの向き」に揃えてから比較します。

2. **位置ずれの自動補正**
   CADから出力し直すと図面全体が数mmずれることがあります。
   両方に1本ずつしかない「同じ長さ・同じ向きの線」を手掛かりに
   全体のずれ量を求め、補正してから比較します。
   （補正した場合は結果画面に表示されます）

3. **許容差つきの照合**
   座標が 0.9pt 以内に収まる図形は同一とみなし、再出力時の
   微小な誤差を変更として拾わないようにしています。

4. **PDFの作り手の違いを吸収する**
   同じ図面でも、出力したソフトによって中身の作りが変わります。
   次の2つは図面の変更ではないので、変更として数えません。
   - **文字の区切り方**：「SL-2150芯」が `["SL-2150","芯"]` と
     分かれている場合があります。両方を同じ規則でつなぎ直し、
     さらに同じ場所の文字を並べて比べて、中身が同じなら
     「区切り差」として扱います。
   - **極小の図形**：寸法点のドットなどが、別の描き方
     （1pt未満の微小な曲線の集まり）で出力されることがあります。
     1pt未満の図形だけの差は対象から外します。

5. **変更箇所のまとめ方**
   近い変更点どうしをまとめます。連続寸法線は端点が数珠つなぎになり
   図面の端から端までが1箇所になってしまうため、広がりすぎた塊は
   より短い距離で分け直しています。

6. **図枠外の除外**
   図枠の外に置かれた申し送りメモやスタンプは印刷されない領域なので
   比較の対象から外し、件数だけ知らせます。

7. **位置の言い換え**
   変更箇所に最も近い通り芯（`SX1` `SY2` `NX8` など、X・Yを含む記号＋数字）
   を探して「通り芯 SX3 / SY2 付近」のように表示します。
   この命名規則でない図面では通り芯名は表示されません。

## 作り直す場合

`src/` を編集して、以下を実行すると単一HTMLが組み上がります。
Node.js が必要なのは**この作業をするときだけ**で、使う人には不要です。

```
node build.mjs
```

| ファイル | 内容 |
|---|---|
| `src/diff-core.js` | 差分抽出のアルゴリズム本体 |
| `src/app.js` | 画面の操作と出力（PDF・画像）まわり |
| `src/index.template.html` | 画面の枠組みとスタイル |
| `vendor/` | pdf.js / pdf-lib / JSZip（同梱するライブラリ） |
| `build.mjs` | 上記をまとめて1つのHTMLにする |

調整用のしきい値は `src/diff-core.js` の冒頭にまとめてあります。

## 動作を確認した図面

| 組み合わせ | 条件 | 結果 |
|---|---|---|
| A1・2ページ・同じ出力ソフト | 図面全体が3mmずれてプロット | 変更箇所を過不足なく検出 |
| A3・1ページ・出力ソフトが違う | 一方が90°回転して保存 | 変更箇所8件、うち実際の変更7件 |

## 制限

- **ベクターPDF専用**です。スキャンした紙図面（画像だけのPDF）は比較できません。
- ページの並びが同じであることを前提にしています。ページを差し込んだ・
  抜いたPDF同士では、ずれた以降のページが全面変更として出ます。
- 補正できるのは **90°単位の回転と平行移動** までです。
  縮尺が違う図面同士（A1版とA3版など）は比較できません。
- 出力ソフトが違うPDF同士では、文字の区切り方の違いが
  数件ほど「変更」として残ることがあります（一覧では判別できる形で出ます）。
- 「図形のみの変更」で、ハッチングが連続して変わった箇所は
  枠が横長に広がることがあります。文字を伴う変更は正確に囲まれます。
